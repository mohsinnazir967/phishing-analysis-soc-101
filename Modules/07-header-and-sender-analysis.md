## Overview

Email headers are the most important artifact for determining the **true origin** of a suspicious email. Almost all visible header fields can be spoofed — but the `Received:` chain added by mail servers is reliable.

---

| Client | Method |

| **Gmail** | More (⋮) → Show Original |
| **Outlook on the Web** | More actions → View Message Source |
| **Command line** | `cat sample.eml` |
| **Sublime Text** | `subl sample.eml` (use Email Header syntax) |

## Key Headers Reference

### `Date`
When the message was composed/sent. Document for timeline correlation.

### `From`
The **claimed** sender address — this is the most commonly spoofed header. Never trust it alone.

### `To`
The recipient(s). Use for scope determination.

### `Subject`
Acts as a fingerprint — useful for searching the email gateway for similar messages.

### `Message-ID`
Unique identifier generated by the **first MTA** the message traverses.

```
<unique-id@originating-domain.com>
```

- Should always be unique per email
- The domain after `@` should match the originating server
- **Duplicate Message-IDs** in your gateway = strong indicator of forgery

### `Reply-To`
Where replies are directed — often different from `From:` in spoofing attacks because the attacker controls the `Reply-To` mailbox but not the spoofed `From:` domain.

### `Return-Path`
The bounce/delivery failure address. Should match the sending domain. Mismatch = suspicious.

### `X-Sender-IP` / `X-Originating-IP`
Custom header added by some providers (Microsoft typically includes this, Google does not) indicating the **original sender IP address**.

---

## The Received Headers — Most Important

Each MTA the email passes through **prepends** a `Received:` header. They are read **bottom-up** — the oldest (closest to the sender) is at the bottom.

```
Received: from mail.trusted-server.com (by our-mx.company.com)  ← most recent (top)
Received: from smtp.relay2.net (by mail.trusted-server.com)
Received: from attacker-server.ru (by smtp.relay2.net)          ← oldest (bottom) = true origin
```

**Trusted boundary rule:**
- Only trust `Received:` headers generated by **your own infrastructure** or known trusted MTAs
- Anything below the first trusted hop may have been spoofed by the attacker

## Practical IP Investigation

Once you identify the originating IP from the `Received:` chain or `X-Sender-IP`:

### 1. Reverse DNS Lookup
```bash
# Install whois if needed
sudo apt install whois

# Lookup
whois 185.220.101.45
```

Or use [DomainTools WHOIS](https://whois.domaintools.com)

**Look for:**
- Country of origin
- ISP / hosting provider
- Resolved hostname (rDNS)
- ASN (Autonomous System Number)

### 2. IP Reputation Check
- [VirusTotal](https://virustotal.com) — URL/IP tab
- [Cisco Talos](https://talosintelligence.com)
- [AbuseIPDB](https://abuseipdb.com)

## Worked Example — Chase Bank Spoof

**What the email claims:**
```
From: alerts@chase.com
Subject: Your Bank Account Has Been Blocked
```

**What the headers reveal:**
```
Received: from mail-4140.protonmail.ch (by outlook.com)
X-Sender-IP: 185.70.40.140
Return-Path: <bounce@proton.me>
```

**Investigation:**
1. Originating IP `185.70.40.140` → resolves to `mail-4140.protonmail.ch`
2. WHOIS → Switzerland, ASN: Proton AG
3. Conclusion: Email originated from ProtonMail — **not Chase Bank**
4. `Reply-To` and `Return-Path` point to `proton.me` — inconsistent with `chase.com`

**Verdict: MALICIOUS — sender spoofing**
